# Protocol Decision: independently verified stable patch packages

## Choice and reason

The compiler accepts protocol and organisation packages independently on the
stable `2.0.x` line. Each version must match `2.0.(0|[1-9][0-9]*)` exactly,
and its manifest version must equal its own packaged `VERSION` value.
Different patch numbers are permitted. Other major/minor versions, leading
zeros, prereleases, build metadata and malformed versions are rejected.
The admitted line is fixed in compiler source, never supplied by a manifest
allowlist. A different line requires a future protocol Decision and release.

An organisation patch can repair operating procedures without changing the
fixed protocol contract or synchronising release numbers. The published
2.0.0 compiler instead required both manifest versions to equal `2.0.0`,
preventing compilation of the independently versioned organisation 2.0.1.
An exact patch equality requirement was rejected because it makes unrelated
package publication depend on each other. Accepting arbitrary semver ranges
was rejected because unsupported contracts must fail closed.

## Integrity and interface

Both installed package roots contain their exact `VERSION` and manifest,
plus every manifest-published file at its declared relative path. Existing
protocol `root_protocol`/`repository_block` and organisation `organization`
entries identify the finite compiler inputs; the manifest supplies skills
for the sentence check. No organisation key or installation root changes.
All manifest paths and file SHA256 values remain verified before output.

Version admission establishes compatibility, not authenticity. Consumers
still pin and verify the exact source commit, immutable release archive and
manifest SHA256. Replacing files and recomputing an attacker-selected
manifest does not establish a trusted package. The compiler has no mutable
version exception or digest bypass.

## Forward release and boundaries

Protocol 2.0.1 supersedes only the compiler's exact paired-version predicate
and adds packaged VERSION agreement. Its language contract remains 2.0.0:
eight nouns, Plan group, thirteen verbs, five structural acts, states,
roles, outcomes and query-only assurance are unchanged. Package patches
do not rename the fixed language/wire contract. Source semantic checks
distinguish that contract coordinate from the independently patched package.

The original 2.0.0 tag, archive, manifest, records and author history remain
immutable. The new commitment and Oracle are `contract/patch-compatibility.md`.
SO117 remains the unresolved observation in
`contract/gaps/SO-000117-skill-verb-declaration.md`; this Decision grants no
role/procedure exemption, waiver or resolution. Finite producer qualification
uses synthetic inputs and optionally frozen unpublished organisation source;
it requires neither a future organisation release nor native/live canary
qualification. Stage2 and Stage3 remain held.
