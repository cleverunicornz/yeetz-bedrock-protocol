# v1.18.2 to v2.0.0-draft

**Draft. Not selected.** This note proposes a protocol Decision for the human authority's review: the Bedrock v2
contract. Until a release without the `-draft` suffix is tagged, nothing here is in force, the v1 protocol block
and namespace files remain the published protocol, and consumers change nothing.

## The proposed Decision

Bedrock becomes an act-based protocol: eight nouns, the Plan group, thirteen verbs (twelve performed acts and the
`assure` transition), five structural acts, states derived from acts, a lineage envelope on every act, a 10-minute
edit window, levels as a property, three pinned reference kinds, and fixed queries. It is stated in prose and in a
machine-readable contract that are checked against each other.

- `contract/bedrock-v2.md` (new): the contract in prose, with the tensions it resolves and its open questions.
- `contract/bedrock-v2.yaml` (new): the same contract, machine-readable and storage-neutral.
- `contract/bedrock-v2.schema.json` (new): JSON Schema (2020-12) for one act node and every record it can make.
- `contract/examples/` (new, not published): nine worked act sequences, including a non-software case and three
  refused acts.
- `contract/check.py` (new, not published): proves the prose, YAML, schema and examples agree, replays every example
  through a reference projector, and requires every transition to be exercised.
- `AGENTS.md`, `README.md`: the contract as a content class and the `contract` manifest key.
- `VERSION` 2.0.0-draft, `manifest.json` (version and the new `contract` list; every digest re-checked against its
  file).

## v1 to v2 vocabulary

| v1 | v2 | Change |
|---|---|---|
| Promise, Oracle, Witness, Decision, Invariant, Gap, Candidate, Reference | the same eight nouns | Fields shortened to thread-sized records; states derived from acts. |
| Plan (record class) | Plan (group) | Groups Candidates and Promises with optional `waits_on`; asserts nothing. |
| `observe` | `produce` | A Witness is retained before, and independent of, any verdict. |
| `surface` | `declare` | Unchanged meaning. |
| `propose` | `formulate` | Unchanged meaning; walk the scope first, refine instead of duplicating. |
| `test` | `produce` + `judge` | Production and judgment are separate acts; `inconclusive` is a verdict on the Witness. |
| `decide` | `decide` | Records dispositions; never mints. |
| `promote` | `decide` + `mint` + `define` | Three acts with their own meanings and histories; a batch may record them together. |
| `bound` | `stipulate` | Unchanged meaning; a Decision is optional basis. |
| `implement` | (domain work) + `produce` | Implementation is not a protocol verb. |
| `challenge` | `declare`, `produce`, `judge`, `formulate` | A procedure over the verbs, not a verb. |
| `plan` | structural acts `group`, `regroup` | A Plan is a group, not a claim. |
| (new) | `evaluate`, `refine`, `revoke`, `supersede`, `assure` | Evaluation as its own act; refinement adds without changing a claim; withdrawal and replacement are uniform acts; assurance is a transition. |

| v1 Promise state | v2 |
|---|---|
| `hypothesis`, `qualifying`, `qualified` | Candidate states `formulated`, `evaluating`, `evaluated` |
| `implementing`, `implemented` | `asserted` (implementation is domain work, read from its Witnesses) |
| `assuring`, `assured` | `assuring`, `assured` |
| `refuted`, `withdrawn` | `revoked` with a reason and a Decision basis |
| `superseded` | `superseded` |

## For consumers when a final v2 is released

Not before then: v2 changes where records live (a store per organisation, written through acts) and is adopted only
after it runs beside the current system, is canary-tested, and is approved. Imported v1 records keep their original
coordinates, protocol version and known history boundaries; the import invents no missing Candidates, Decisions,
Witnesses or dates.
