# v1.12.0 to v1.12.1

The protocol and organization layers are provided at user level by the agent
container, above every repository. A repository's root `AGENTS.md` holds only
the repository block.

Composition rule: the user-level `AGENTS.md` is exactly
`templates/root-protocol.md` followed by `templates/organization.md`, with the
skills under `skills/` installed beside it. A repository's root `AGENTS.md` is
never part of that composition; the harness reads it separately, from the
repository.

## Moves

- `organization/AGENTS.md` -> `templates/organization.md`: the organization
  layer is a template beside `templates/root-protocol.md` and
  `templates/repository-block.md`.
- `organization/skills/<name>/SKILL.md` -> `skills/<name>/SKILL.md`.
- `manifest.json`: `organization` becomes the single organization template
  entry, and the skills are listed under `skills`.

## One job per template

- `templates/root-protocol.md` states the Bedrock protocol and how to engage
  with it. It no longer carries git history practice or pull-request merge
  authority; those are organization rules. Its closing paragraphs now say the
  protocol block is supplied at user level, a repository's root `AGENTS.md`
  holds only the repository block, and agents edit only that block. Fork
  rules point to the organization layer.
- `templates/organization.md` states the organization operating rules — Paseo
  and profiles, security fallbacks, the committee, usage-limited Claude
  sessions, full access, autosave and protected branches, branches never
  deleted, pull requests left open, the workbench and its 3-minute cap, CI
  runner labels, Exa, secrets — and a skill index, and points to the
  protocol block in one line.
- Skills carry procedures and details and never restate a rule stated in
  `templates/organization.md`.

## Other protocol files

- `situation/AGENTS.md` — `Root AGENTS.md blocks` becomes
  `Instruction layers`: the protocol block is supplied at user level, the
  repository block is the only content of the root `AGENTS.md`, and
  organization rules, including fork rules, live in the organization layer.
- `situation/references/AGENTS.md` — every-session guidance belongs in the
  repository block; organization-wide rules live in the organization layer.

## Adopters

Adopters resynchronize the namespace files byte-for-byte through their
protocol lock. A repository that still carries `bedrock-protocol` or
`bedrock-organization` blocks in its root `AGENTS.md` removes them in its next
change to that file, keeping only `bedrock-repository`; the user-level layers
already supply the removed content. Records need no migration and remain
valid unchanged.

These changes were selected by the organization's human authority on
2026-09-27.

## Predeclared acceptance

1. `templates/root-protocol.md` states that the protocol block is supplied at
   user level and that a repository's root `AGENTS.md` holds only the
   repository block; any remaining statement that a protocol or organization
   block is carried in or synchronized into a repository fails.
2. `templates/root-protocol.md` contains nothing about runtimes, runners,
   harnesses, models, secrets, git practice, or pull-request merge authority.
3. `templates/organization.md` restates no protocol concept and refers to the
   protocol block in at most one line.
4. Each rule in `templates/organization.md` is stated nowhere else in
   `templates/` or `skills/`; a skill restating one fails.
5. No protocol file places fork rules in a root organization block.
6. `templates/repository-block.md` keeps its v1.12.0 digest.
7. `manifest.json` lists every file under `templates/organization.md` and
   `skills/` with digests matching their bytes; `organization/` no longer
   exists.
8. The release introduces no new record class, lifecycle state, checker, or
   gate.
