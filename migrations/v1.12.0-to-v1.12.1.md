# v1.12.0 to v1.12.1

The protocol files now describe the instruction layers introduced in v1.12.0.
The root protocol block and the organization layer are provided at user level
by the agent container, above every repository. A repository's root
`AGENTS.md` holds only the repository block. Organization rules, including
the fork rules, live in the organization layer, not in a repository.

Composition rule: the user-level `AGENTS.md` is exactly
`templates/root-protocol.md` followed by `organization/AGENTS.md`. A
repository's root `AGENTS.md` is never part of that composition; the harness
reads it separately, from the repository.

Changed protocol files:

- `templates/root-protocol.md` — fork rules point to the organization layer;
  the three-tagged-blocks paragraph becomes the layer statement with the
  composition rule; the ownership paragraph says agents change neither the
  protocol block nor the organization layer and edit only the repository
  block.
- `situation/AGENTS.md` — `Root AGENTS.md blocks` becomes
  `Instruction layers`; fork rules and fork orientation point to the
  organization layer and the repository block.
- `situation/references/AGENTS.md` — every-session guidance belongs in the
  repository block; organization-wide rules live in the organization layer.

Adopters resynchronize the namespace files byte-for-byte through their
protocol lock. A repository that still carries `bedrock-protocol` or
`bedrock-organization` blocks in its root `AGENTS.md` removes them in its next
change to that file, keeping only `bedrock-repository`; the user-level layers
already supply the removed content. Records need no migration and remain valid
unchanged.

These changes were selected by the organization's human authority on
2026-09-27.

## Predeclared acceptance

1. `templates/root-protocol.md` states that the protocol block and the
   organization layer are provided at user level, that the user-level
   `AGENTS.md` is the root protocol block followed by the organization
   layer's `AGENTS.md` and never includes a repository's root `AGENTS.md`, and
   that a repository's root `AGENTS.md` holds only the repository block. Any
   remaining statement that an organization block is synchronized into a
   repository fails.
2. No protocol file places fork rules in a root organization block; fork rules
   are referenced in the organization layer.
3. `situation/AGENTS.md` and `templates/root-protocol.md` state the same
   layering; a contradiction between them fails.
4. `templates/repository-block.md` and every organization layer file keep
   their v1.12.0 digests.
5. `manifest.json` digests match the bytes of every listed file.
6. The release introduces no new record class, lifecycle state, checker, or
   gate.
