# Protocol Decision: graph authority and compiled instructions

## Choice and grounds

The fixed v2 contract is adopted without changing its eight nouns, Plan group,
thirteen verbs, five structural acts, states, outcomes or role guidance.
All records live in the task graph at a qualified scope. The graph surfaces
binding invariants and open work; memory resolves what happened through
transcript lineage; the board carries the session outline.

Each verb skill includes an executable procedure against the pinned single
task-graph tool. Structural operations have procedure skills beside them.
Nouns have no skills. `assure` remains a query of a transition, never an act.
Procedures bind actual previous response IDs rather than assuming allocation
order. Protocol calls and organisational runtime policy have distinct owners.

AGENTS.md compiles brief Bedrock axioms and skill pointers, the organisation's
few pointers, and repository identity/bootstrap information. It carries no
copied records or skill sentences. The compiler verifies package manifests
and checks all supplied skills for sentence duplication; CI exercises this.

Copying skill manuals and records into instructions was rejected because
competing authorities drift. Retaining Git as live knowledge was rejected
for qualified scopes because acts and cross-scope queries define v2.

## Distribution and migration

`manifest.json` publishes protocol files and procedures only. Organisation
policy comes from its separate paired 2.0.0 package, rooted at `org/`.
Legacy organisation and namespace bytes remain in Git and history, but are
absent from the 2.0.0 manifest. Never install v1 namespace instructions into
a qualified v2 scope. Git records freeze at the accepted scope coordinate;
history and imported provenance stay available.

User instructions compile the Bedrock and organisation parts; a repository's
own instruction file compiles its repository part. A full rendering supports
review and questioning. `compiler/README.md` specifies installation/layout.
Every consumer verifies exact release manifests.

This Decision supersedes source-authoring prohibitions on executable tool
procedures and qualification workflows; semantic checks remain required.
The source repository remains exempt from consuming its own protocol.

## Authority and stop point

Releasing 2.0.0 activates nothing. Authority is scope-specific and changes
only after reconciliation, runtime/identity qualification and a receipt.
Stage0 then a light repository canary may go live when qualified. All six
gates in `contract/stage0.md` must pass; failures are fixed and re-tested.
After the canary, stop and report before Stage2 or Stage3.

Protected source is authored, reviewed and merged by console lanes.
This procedure delegates no console endpoint or privilege to repository pods.
