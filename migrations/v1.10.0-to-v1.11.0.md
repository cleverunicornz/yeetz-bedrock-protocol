# v1.10.0 to v1.11.0

Promises are written at the granularity of a capability a consumer can
meaningfully rely on — an interface, an operation, an observable behavior —
never one promise per file, function, or endpoint. A promise may adopt a
specification by reference for detailed requirements, pinning the exact
adopted version under the repository reference discipline. Adopted
requirements are judged like any stated requirement, and selecting a
different version of an adopted specification is a contract change that
follows the assured-promise supersession path.

A Candidate before promotion carries no reliance or assurance obligations;
after promotion the resulting Promise is the selected commitment. Code
already present in the repository is evidence, not selection: the Decision,
not the implementation, marks the boundary.

Working a change means traversing the affected behavior's links — its
Promise, Oracle, Witnesses, and the Decisions, Candidates, and Gaps linked
to them — and a record set that cannot be traversed is incomplete for that
behavior. A contract composed over several repositories selects and links
local Promises instead of restating them, keeping one authority per
behavior. A delta that affects claimed behavior repairs missing local
lineage within its own run; missing lineage the delta does not affect is
recorded as a Gap for separately assigned work.

Records may be created after the behavior they describe exists. A
retrospective Promise is valid when it states its creation context honestly
and cites only evidence that exists, and an oracle designed after
implementation is ordinary; it still requires real witnesses on real runs
before assurance. The Oracle judges the Promise's stated contract —
including adopted requirements — never the implementation's current
behavior as the source of the contract.

Adopters resynchronize byte-for-byte through their protocol lock. No record
migration is required, and existing records remain valid unchanged.

These changes were selected and approved for this release by the
repository's human authority on 2026-09-20.

## Predeclared acceptance

1. A delta affecting claimed behavior that lacks local Promise/Oracle/Witness lineage is closed by establishing the missing records within its run; discharging it solely as an incidental Gap fails.
2. Missing lineage for behavior the delta does not affect is recorded as a Gap observation without assigned remedy; treating it as automatic work fails.
3. A Promise at file/function/endpoint granularity without a relied-on capability claim fails review; a capability-granularity Promise with detail adopted by pinned-specification reference passes.
4. A Promise adopting a pinned specification is judged including the adopted requirements within Scope; changing the adopted specification version of an assured Promise without superseding Promise, Decision, replacement Oracle, and new Witnesses fails as contract drift.
5. A record chain claiming acceptance because the implementation currently behaves some way, without an Oracle passing on a real Witness, fails; accepted behavior is what the Promise states.
6. Retrospective lineage records for pre-existing behavior carry true creation context and cite only real evidence; any backdated, invented, or fabricated-predeclaration record fails.
7. A higher-level organization/program/project contract composes local Promises by reference; restating local behavior without linking fails; a local change still traces to local lineage.
8. Working a change traces the affected behavior's full link set (Promise, Oracle, Witnesses, related Gaps/Candidates/Decisions); skipping a linked record the change invalidates fails.
9. The release introduces no schema checker, gate, graph engine, new record class, or extra review pass; record classes and lifecycle states are unchanged.
