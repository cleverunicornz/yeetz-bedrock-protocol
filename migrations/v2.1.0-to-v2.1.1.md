# Protocol Decision: Bedrock STE100 Communication

## Choice and grounds

Publish Bedrock STE100 Communication as a shared protocol convention. It
applies to agent-authored records and communication in all Bedrock settings,
including individual use outside an organisation. Locating the baseline
only in an organisation package would omit it from other adopters.

The initial profile adopts a small set of writing conventions from
ASD-STE100 Issue 9, with explicit source lineage and adaptations. It lists
Bedrock's nouns and verbs and directs readers to the definitions and
individual skills relevant to their assignment. It preserves human input
and meaningful uncertainty while reducing routine ambiguity in agent prose.

Publish `ste100-review` as a specialisation of `evaluate`. A proposer and an
independent agent examine a proposed convention's preventive value and its
costs. The owner may request revisions and further evaluation before a
Decision. Gaps, Candidates, findings, Decisions and qualification remain
within the existing protocol. A failure does not automatically assign work
or require another convention.

## Alternatives considered

- Organisation-only guidance: insufficient for personal and other
  independent adopters of the protocol.
- Full STE conformance: exceeds the selected scope and would constrain
  useful communication beyond the evidence considered here.
- A separate improvement protocol or new verbs: existing acts already
  express the proposed review and revision loop.
- A fixed debate count or compulsory convergence: the decision depends on
  the case, counterexamples and accepted risk.

## Published changes

- `contract/communication/ste100-writing.md`: profile 1 and vocabulary
  pointers. It is shared guidance, not a new performed verb.
- `contract/communication/asd-ste100-issue9.md`: source edition, provenance,
  rule correspondence and deliberate adaptations.
- `contract/communication/ste100-review/SKILL.md`: the `evaluate`
  specialisation and its links to the existing acts.
- `templates/root-protocol.md`: two short pointers to the writing
  convention and review skill. The existing noun and verb index stays.
- `contract/bedrock-v2.md`: the shared convention belongs to the protocol
  at every scope, with references to its published guidance.
- `compiler/README.md` and `compiler/generate_manifest.py`: publish and
  retain the communication files under the existing `contract` manifest
  section, including the review skill at its original path.

This is an authoring-guidance patch. The act contract remains 2.1.0: nouns,
verbs, states, outcomes, roles, schema, tool envelopes and receiver semantics
are unchanged. The package is 2.1.1, within the admitted stable patch line.
The convention adds no language-based refusal of a graph act.

## Qualification

The source checks and compiler tests must still pass. The release archive
must include both entry points and their source lineage, and its compiled
instructions must resolve those pointers from a manifest-only package.
Manifest regeneration and the compiled example must agree byte for byte.
These checks qualify delivery; they do not establish a reduction in human
or agent misunderstanding. Actual use and the review procedure retain that
evidence when observed. This note records no unperformed behavioural trial.

The normal source-review and release gates apply. Publishing a source
release does not update an adopter's installed pin or activate a runtime.
